# Rate Limit 저장소 전략

## 결정

- abuse rate limit 저장소는 `Redis`를 사용한다.
- 단일 인스턴스 기준으로도 Redis를 사용해 서버 재시작 시 제한 상태가 초기화되지 않도록 유지한다.
- 운영 설정은 `abuse.rate-limit.storage=redis`로 명시한다.

## 이유

- 메일 재발송, 비밀번호 재설정, 로그인 제한은 서버 재시작으로 바로 초기화되면 abuse 방어 품질이 떨어진다.
- 향후 인스턴스가 늘어나도 인스턴스 간 제한 상태를 공유할 수 있다.
- 현재 프로젝트는 이미 Redis를 사용하고 있어 운영 의존성을 추가로 늘리지 않는다.

## 제외한 선택지

### In-Memory

- 단일 인스턴스에서는 구현이 단순하다.
- 하지만 서버 재시작 시 제한 상태가 모두 사라진다.
- 다중 인스턴스 확장 시 인스턴스별로 제한 상태가 갈라진다.

## 운영 기준

- Redis 장애 시 기본 동작은 `fail-open=true`로 유지한다.
- 키 prefix는 `abuse.rate-limit.redis-key-prefix`로 분리해 운영 환경별 충돌을 피한다.
- 임계값은 `abuse.rate-limit.*` 하위 정책에서 별도로 조정한다.
