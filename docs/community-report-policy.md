# 커뮤니티 글·댓글 신고 정책

관련 이슈: #1619 / 상위 이슈: #1618

## 신고 사유와 접수

| 사유 | 의미 |
|---|---|
| SPAM | 광고·도배 |
| ABUSE | 욕설·괴롭힘 |
| INAPPROPRIATE_CONTENT | 부적절한 콘텐츠 |
| PERSONAL_INFORMATION | 개인정보 노출 |
| OTHER | 기타 |

- 모든 사유에 상세 설명 1~500자가 필요하다. 공백만 있는 설명은 거절하고 앞뒤 공백을 제거한다.
- 인증된 사용자를 신고자로 사용한다. 사용자 ID를 요청 값으로 신뢰하지 않는다.
- 신고 하나는 글 또는 댓글 하나만 참조한다. 댓글 신고는 댓글의 글을 별도 신고 대상으로 저장하지 않는다.
- 같은 사용자는 같은 대상에 한 번만 신고할 수 있다. 수락·반려 후에도 재신고할 수 없다.
- 서로 다른 사용자는 같은 대상을 신고할 수 있고, 같은 사용자는 글과 그 댓글을 각각 신고할 수 있다.
- Repository의 중복 조회는 사전 안내용이다. 동시 접수 중복은 DB UNIQUE 제약으로 최종 차단한다.
- 대상 존재·공개 여부와 인증 검증 및 중복 오류 변환은 #1620에서 구현한다.

## 상태 전이

| 현재 상태 | 허용 상태 | 의미 |
|---|---|---|
| PENDING | ACCEPTED | 관리자 수락 |
| PENDING | DECLINED | 관리자 반려 |
| ACCEPTED / DECLINED | 없음 | 재처리·취소 금지 |

- 생성 시 PENDING이며 처리자·처리 시각은 비어 있다.
- 처리 시 관리자 ID와 처리 시각을 함께 기록한다. 접수보다 앞선 처리 시각은 허용하지 않는다.
- Entity의 상태 전이 검증과 낙관적 잠금(version)을 함께 사용한다.
- 관리자 권한 검증, 동시 수정 오류 변환과 대상 숨김을 포함한 트랜잭션은 #1622에서 구현한다.
- 다른 사용자의 대기 신고를 자동으로 수락·반려하지 않는다. 같은 대상에 대한 후속 반려로 이미 숨긴 대상을 복구하지 않는다.

## 숨김 및 일반 조회 노출 기준

- 신고 접수만으로 자동 숨김하지 않는다. 관리자 수락 시 신고 대상만 숨긴다.
- 숨김 글은 일반 목록에서 제외하고 상세·하위 댓글 조회는 없는 글과 동일하게 처리한다.
- 숨김 글에 댓글 작성·좋아요·커뮤니티 경유 장소 조회를 허용하지 않는다.
- 숨김 댓글은 일반 댓글 목록에서 제외하고 부모 글과 다른 댓글은 유지한다.
- 관리자 조회에서는 숨김 대상과 신고 이력을 유지한다.
- 반려는 대상의 노출 상태를 변경하지 않는다. 자동 사용자 제재와 복구 API는 이번 범위에 포함하지 않는다.
- 숨김은 물리 삭제가 아니다. 신고 FK는 대상의 물리 삭제를 제한하여 신고 이력을 보존한다.

## 데이터와 구현 범위

- community_report는 글·댓글 FK 중 정확히 하나만 갖는다. 사용자 ID는 기존 커뮤니티와 동일하게 숫자로 보관한다.
- 상태별 최신 목록, 대상별 신고 조회를 위한 인덱스를 제공한다.
- 이번 이슈는 신고 데이터 구조·상태 전이·정책을 구현한다. 기존 글·댓글 API의 노출 동작은 아직 변경하지 않는다.
- #1621에서 관리자 콘텐츠 조회, #1622에서 숨김 저장 및 모든 일반 접근 경로의 필터를 함께 적용한다.
- #1623에서 통합 흐름과 API 문서·회귀 검증을 수행한다.
