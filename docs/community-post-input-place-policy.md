# 커뮤니티 게시글 입력 및 장소 선택 정책

이 문서는 [#1535](https://github.com/Type-Nu11/pingdom-api/issues/1535)에서 확정한
커뮤니티 게시글 입력과 연결 장소 선택 기준을 정의한다. 목록·댓글 조회, 삭제 데이터 노출,
장소 조회수와 장소 언급 게시글 수 정책은 [#1536](https://github.com/Type-Nu11/pingdom-api/issues/1536)에서 별도로 다룬다.

## 적용 범위

- 커뮤니티 게시글 등록 요청의 제목·본문·카테고리·연결 장소 입력
- 카테고리에 따른 연결 장소 필수 여부
- 연결 장소의 이름을 응답에 표시하는 기준

## 게시글 입력 계약

| 항목 | 필수 | 제한 | 정책 |
|---|---:|---|---|
| 카테고리 | 예 | 유효한 카테고리만 | 게시글의 분류 기준이다. |
| 게시글 제목 | 예 | 최대 50자 | 사용자가 입력하는 게시글 자체의 제목이다. |
| 게시글 본문 | 예 | 최대 5,000자 | 사용자가 입력하는 게시글 내용이다. |
| 연결 장소 ID 목록 | 카테고리별 상이 | 개수 제한 없음 | 장소 이름을 저장하지 않고 장소 ID만 저장한다. |

제목과 본문은 공백만으로 구성할 수 없으며, 요청 DTO의 Validation으로 검증한다.

## 게시글 제목과 장소 제목의 구분

게시글 제목과 장소 제목은 서로 다른 값이다.

| 구분 | 예시 | 저장·조회 기준 |
|---|---|---|
| 게시글 제목 | `xx 재밌네요` | 게시글 등록 시 입력받아 게시글 데이터로 저장한다. |
| 장소 제목 | `대소고` | 연결된 `placeId`로 장소 데이터를 조회해 응답에 제공한다. |

장소 제목은 게시글 테이블 또는 게시글-장소 연결 테이블에 복사 저장하지 않는다. 장소 이름이 변경되면
게시글 상세 응답에도 변경된 장소 이름이 반영된다.

## 연결 장소 선택 기준

| 게시글 카테고리 | 연결 장소 입력 | 검증 기준 |
|---|---|---|
| 장소 | 필수 | `placeIds`에 1개 이상 존재해야 한다. |
| 장소 외 카테고리 | 선택 | 장소를 연결하지 않아도 등록할 수 있다. |

- 모든 카테고리에서 여러 장소 연결을 허용한다.
- 연결 장소 개수의 상한은 두지 않는다.
- 동일 `placeId`의 중복 연결은 허용하지 않는다. 중복 요청은 Validation 또는 저장 전 검증으로 거절한다.
- 모든 `placeId`는 등록 시점에 존재하고 조회 가능한 장소여야 한다. 존재하지 않거나 사용할 수 없는 장소가 포함되면 게시글과 연결 관계를 함께 저장하지 않는다.

## 구현 시 준수 사항

- 게시글과 연결 장소 관계는 하나의 트랜잭션으로 저장한다.
- 장소 제목은 장소 조회 결과에서 구성하며, 게시글 엔티티에 장소 이름을 중복 보관하지 않는다.
- 입력 오류는 프로젝트의 기존 `ErrorCode`, Global Exception Handler, 공통 응답 형식을 사용한다.
- 다음 기능 이슈에서는 이 문서의 정책을 변경하지 않고 적용한다.
  - #1539 게시글과 장소 연결 관계 및 중복 제약 구성
  - #1541 게시글 등록 요청 검증 및 작성자 식별
  - #1542 게시글 등록 장소 유효성 및 필수 선택 검증
  - #1543 게시글 및 장소 연결 원자적 등록

## 결정 근거

- 게시글 제목과 장소 제목을 분리하면 사용자가 작성한 내용과 연결 장소의 공식 정보를 혼동하지 않는다.
- 장소 이름을 복사하지 않으면 장소 정보 변경 시 중복 데이터 불일치가 생기지 않는다.
- 장소 카테고리에서만 최소 1개를 강제하면 장소 중심 게시글의 목적을 보장하면서, 여행·돈 등 다른 카테고리의 작성 흐름은 유지할 수 있다.
