# 입지 분석 보고서 소유권

신규 보고서는 생성 요청의 인증 사용자 ID를 `owner_user_id`에 기록합니다. 목록·상세·PDF·HTML·수정·삭제는 이 ID를 조건으로 조회하며, 요청 이메일이나 현재 계정 이메일의 일치만으로 보고서에 접근할 수 없습니다. 제목·연락처 수정은 소유자를 변경하지 않습니다. 기존 email 파라미터와 계정 이메일 확인은 클라이언트 호환을 위해 유지합니다.

## 기존 보고서와 사용자 삭제

V142는 기존 보고서에 소유자를 자동 지정하지 않습니다. 이메일 대소문자 중복과 탈퇴 후 같은 이메일의 재가입 때문에 현재 이메일 일치는 생성자 증거가 될 수 없습니다. `owner_user_id IS NULL`인 행은 보존하면서 모든 사용자 조회에서 제외합니다. 복구는 신뢰할 수 있는 생성자 증거와 승인된 절차가 정해진 뒤 별도 작업으로 수행해야 합니다.

사용자 최종 삭제 이후에도 귀속 식별값을 보존할 수 있도록 사용자 테이블에 새 FK나 cascade를 추가하지 않습니다. 보고서의 보존기간·삭제·익명화와 계정 이메일 정규화/고유성 변경은 별도의 정책 결정 대상입니다. 이 변경은 기존 사용자 계정을 병합하거나 재가입 계정에 보고서를 승계하지 않습니다.

## 적용과 롤백

1. 보고서 생성·접근 트래픽을 중지하고 V142를 적용합니다. 기존 보고서 수와 소유자 미확정 행 수를 기록합니다.
2. 사용자 ID로 저장·조회하는 버전을 전체 인스턴스에 적용한 뒤 트래픽을 재개합니다. 이메일만 사용하는 구버전과 혼합 실행하지 않습니다.
3. 신규 보고서에 소유자 ID가 기록되고 격리 보고서와 타인 보고서가 모든 경로에서 조회되지 않는지 확인합니다.
4. 롤백 시 먼저 보고서 생성·접근을 차단합니다. V142 컬럼과 귀속 데이터는 유지합니다. 이메일 조건만 사용하는 버전으로 트래픽을 재개하면 기존 취약점이 다시 발생하므로 보안 수정 없이 재개하지 않습니다.
